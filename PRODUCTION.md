# Подготовка к публикации

Исходная версия страницы готова для статического размещения или подключения к CMS РГСУ. Автономный HTML предназначен для согласования и демонстрации; для публикации используйте папку `rgsu-skb`.

## 1. Подключение формы

Создана таблица «Заявки с сайта СКБ Технопарка РГСУ». Готовый обработчик лежит в `backend/Code.gs`, а его настройки — в `backend/appsscript.json`.

Создайте привязанный к таблице проект Google Apps Script, перенесите в него эти два файла и опубликуйте как веб-приложение:

- выполнять от имени владельца;
- доступ — всем пользователям;
- после публикации скопировать адрес, заканчивающийся на `/exec`.

В `index.html` у формы `#application-form` задайте этот адрес:

```html
<form ... data-endpoint="https://script.google.com/macros/s/ВАШ_АДРЕС/exec">
```

Обработчик принимает JSON методом `POST`, сохраняет заявку в таблицу, кладёт приложенный файл в отдельную папку Google Диска и отправляет уведомление на `technopark@rgsu.net`. Поля формы:

- `type`: `student` или `partner`;
- `name`, `email`, `phone`;
- `organization` — для организаций;
- `student_work_type`, `faculty`, `student_topic`, `supervisor`, `deadline` — для студентов;
- `task`, `attachment`, `consent`, `source_url`.

Размер файла ограничен 4 МБ. Разрешены документы, презентации, изображения и архивы, перечисленные в форме. Вложение сохраняется на Google Диске и прикладывается к уведомлению.

Если `data-endpoint` пуст, сайт использует резервный сценарий: открывает почтовую программу с письмом на `technopark@rgsu.net`. Файл в этом режиме пользователь прикладывает вручную.

## 2. Заголовки безопасности

Файл `_headers` содержит рекомендуемые заголовки для Cloudflare Pages, Netlify и совместимых платформ. Для Nginx, Apache или CMS перенесите те же значения в серверную конфигурацию. Если API находится на другом домене, добавьте его точный origin в директиву `connect-src` CSP.

## 3. Кэширование

Статические ресурсы можно кэшировать на год только при версионировании имён файлов или URL. HTML должен перепроверяться при каждом открытии. При публикации через CMS используйте её механизм ревизий ресурсов.

## 4. Проверки перед релизом

```bash
npm install
npx playwright install chromium
npm test
npm run build
```

Smoke-тест проверяет desktop, mobile, reduced motion, модальные окна, меню, отсутствие горизонтального скролла и успешный сценарий отправки через тестовый API.

## 5. Контент

Перед размещением редактор РГСУ должен подтвердить даты и формулировки карточек НТС, контактные данные и актуальную редакцию политики обработки персональных данных.
